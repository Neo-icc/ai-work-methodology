导言

一句话说清我做的是什么

我从来不是在"让 AI 帮我写东西"。
我是在把自己的手艺编译成可执行的系统——先想清楚结构和判断标准， 再让 AI 按这个结构去生产，最后用独立验证确认它没有骗我。

这句话解释了一个现象：同样的工具，有人用出"聊天助手"，有人用出"生产线"。 差别不在提示词写得多漂亮，而在你有没有先把"怎么判断好坏"想清楚。 下面的三章，分别对应这件事的三个层面——信念（为什么这么做）、 流程（怎么做）、招式（具体动作）。

第一部分

三个底层信念

这三个信念在几乎每一个项目里都出现过。它们不是原则宣言，是能够从产出物里被指认出来的工作习惯。

信念 01 框架先行，内容后填

动手之前，先把"结构骨架"立好，绝不让 AI 从一张白纸开始发挥。 骨架决定了成品的天花板，内容只决定它好不好看。

现实证据 教案：七段框架（课程信息 → 大纲映射 → 易错点预警 → 教学目标 → 重难点 → 教学过程 → 课后评估）先定死，再填内容。
教师成长：「见己 · 懂学 · 立身」三层，分别对应"理解人 → 理解学习 → 确立价值"。
评估体系：「6 大维度 × 4 项子项 × 3 级等级」的 6×4×3 矩阵。
知识站：P1 全局导航 → P2 单条内容 → P3 关联网络 → P4 人物观点，逐层下沉。

这里最容易被忽略的一点

框架不是自己凭空想的，是从权威标准里借来的。你用了剑桥教师标准（Cambridge Teacher Standards）、 剑桥英语教学框架的四阶能力递进、维多利亚州导师能力框架、国内"青蓝工程"，以及 Edexcel 的 Specification Reference 和 Assessment Objectives。借来的骨架 + 本校的情境，才是一个既专业又落地的框架。

什么算一个好框架

标准只有一个：每一格都知道该填什么类型的信息。如果某一栏你看着它发呆、不确定该写什么， 说明这个框架还没设计完，此时让 AI 去填，它只会用漂亮话糊弄过去。

信念 02 流程替代灵感

一次性对话产出的是"作品"，流水线产出的是"产能"。真正值钱的不是某次惊艳的输出， 而是"无论谁来做、无论做多少次，结果都稳定在 80 分以上"。

现实证据 知识站项目的《提示词工程手册》开篇写着一句话：
"把「靠灵感生成」变成「走流程出内容」"

配套的是四层流水线，每层都有明确的输入输出契约：
P1 全站导航 → nav.json　│　P2 批量条目 → entries.json　│
P3 关联网络 → connections.json　│　P4 人物观点 → claims.json

为什么这一步是分水岭

有流程，你才能做三件事：批量生产（每批 10–15 条，不贪多）、 定位问题（哪一层出错了，一看就知道）、交给别人（换个人照着 SOP 也能跑）。 没有流程，每次都是从头再来，成果无法累积。

信念 03 可验证才算完成

AI 说"做好了"不算数，你自己觉得"看着挺好"也不算数。 只有一个东西算数：一套不依赖 AI 自我评价的独立验证。

现实证据 知识站项目的验收标准是四重验证叠加：
① 机器自检　43 项渲染与交互断言，全过才算完成
② 第三方审计　独立审计脚本 41 项，覆盖内容 / 无障碍 / 布局 / 性能
③ 事实验真　DOI 逐条解析 + Crossref 比对标题、作者、年份，404 即判定失败
④ 人眼终审　17 张逐视图截图，生成可打印的验收报告

手册里还有一句硬话："该格式由 audit.js 硬校验，格式不合规即验收失败。"

这条信念的真正价值

它把"信任"这个人际问题，变成了"验证"这个技术问题。 因为有了验证，你才敢把 AI 的产出直接交给别人用；因为有了验收报告， 对方不需要问你"做完了吗、靠不靠谱"。

第二部分

六阶段工作流

从"我这里疼"到"这东西以后还能用"，中间固定走六步。 这六步不是理论推演，是从已有项目里反复出现的行为模式中归纳出来的。

1
定题 —— 从痛点出发，不从工具出发
Problem before tool

起点永远是一个具体的人和一个具体的场景，而不是"AI 能做什么"。 你几乎从不问"我还能用 AI 干点啥"，而是"这件事我每周都在重复干，能不能让机器接手"。

真实痛点产出的项目
每备一节课要翻考纲、找易错点、编例题，动辄两三小时edexcel-lesson-prep：七科统一的备课 skill
十届毕业生彼此失联，校友资源散落校友圈：邀请制私密社区小程序
家长很焦虑但说不清焦虑在哪家校共育：五维度家长自我觉察问卷 + 计分器
新教师带得好不好，全凭师傅主观印象老带新三层成长框架：可观测的评估体系

判断标准：能不能用一句话说清"谁，在什么场景下，因为什么而受益"。 说不清就别开工——这类项目做出来通常没人用。

2
立框 —— 先搭骨架，不急着生成
Structure before content

这是六步里最关键的一步，也是绝大多数人跳过的一步。具体做三件事：

  1. 找权威骨架——先问"这个领域有没有成熟的、被认可的结构？"。考纲、专业标准、行业框架，能借就借，不要自创。
  2. 确定层级——几层？每层几项？每项分几档？把这个"格子"画出来再往下走。
  3. 定义每个空格——明确每一栏该填什么类型的信息（是事实、是判断、还是策略）。
反例警示：直接对 AI 说"帮我写一份物理教案"，得到的一定是一篇泛泛而谈、 看着像教案但上不了课的文章。差别不在 AI 的能力，在于你没有给它一个"值得填的格子"。
3
喂料 —— 上下文决定上限
Context before prompt

你几乎从不空手上阵。每个项目都会先准备一个"知识底座"，然后才让 AI 动笔。 这是你和"提示词技巧派"最根本的差别——你相信素材质量决定输出质量，而不是措辞。

喂什么实际做法
学科知识库教案 skill 内置 references/ 目录，数学、物理、化学、生物、经济、会计、商业七科各自成文件
原始权威文本Edexcel Specification 原文、Assessment Objectives、Examiner's Report 中的典型问题
本校具体情境这个班的水平、往届学生踩过的坑、本校的教学节奏
已有资产写经济学教案时，显式引用乐享知识库里的 AS 经济知识库内容

一句话记住：AI 的水平上限由你喂的料决定，不由你的措辞决定。 提示词技巧只能在素材上限之下做微调。

4
量产 —— 分层流水线，而非一把梭
Pipeline before single shot

当项目规模超过"一次对话能搞定"的量，你的做法是拆成层，逐层生产，每层独立验收。 知识站项目是这套方法最完整的样本：全局导航跑通了，才去做单条内容；单条内容稳定了，才去做关联网络。

  • 每层独立可验收——某一层不合格，重跑这一层就行，不用全部推倒
  • 输出结构化——统一转成 JSON 入库，站点可以随时从数据重建
  • 控制批量节奏——每批 10–15 个单元，不贪多。量大了质量必然滑坡，而滑坡了你根本发现不了
5
质检 —— 不信自评，只信独立验证
Verification before delivery

这一步是你和大多数人拉开差距的地方。多数人的验收标准是"我看着还行"， 你的验收标准是"四重独立验证全部通过"，缺一项就不算完成。

验证层谁来做验什么
机器自检脚本断言功能是否真的按设计工作（43 项断言）
第三方审计独立审计脚本内容、无障碍、布局、性能（41 项）
事实验真外部接口比对引用是否真实存在（DOI 解析 + Crossref 核对）
人眼终审你自己逐视图截图，看整体观感与逻辑连贯
核心原则：让 AI 自己检查 AI，等于没检查。 所有验证都必须由一个"不知情的"独立环节完成——不同的脚本、不同的视角、不同的数据源。
6
沉淀 —— 让这一次的成果，下一次还能用
Asset before artifact

这是你所有方法里最"反人性"、也最有价值的一步。大多数人做完项目就结束了， 你会多问一句：这套东西，下次还能用吗？ 能复用，就把它变成资产。

三种沉淀形态，依次递进：

形态什么时候用例子
Skill 化同一类任务要做三次以上20 个已建 skill：教案、课件、知识解释、数学测验、信息科技备课……
SOP 化流程复杂、需要别人也能跑《提示词工程手册》：分层模板 + 批量生产 SOP + 质检清单
框架化是判断标准而非操作步骤老带新三层框架、6×4×3 评估体系

注意区分：Skill 沉淀"动作"，SOP 沉淀"流程"，框架沉淀"判断"。 三者不能互相替代，一个成熟的工作系统三样都有。

第三部分

十二个可复用的招式

上面是框架，这里是能直接抄走的具体动作。每一条都标注了它在你哪个项目里出现过。

1三栏解剖法
遇到任何"问题类"内容，一律拆成三栏：现象 → 根因 → 对策。 不让 AI 只描述现象，强制它往下推两层。这是你所有文档里出现频率最高的结构。
见于：教案的"易错点预警"（错误表现 / 根因分析 / 预防策略）、校友圈合规评审（风险 / 成因 / 处置）
2权威锚定法
每一个论断都必须挂一个可核查的来源：考纲编号、DOI、标准条款、真题年份。 挂不上来源的论断，要么删掉，要么降级为"建议"。
见于：教案的 Specification Reference 与 AO 映射、知识站的 DOI 逐条验真
3双方案并置法
关键决策点不让 AI 替你选，让它给出两个方案并说明各自代价，由人拍板。 这样既保留了选择权，又拿到了决策依据。
见于：教案的"导入方案 A / 方案 B"、校友圈的产品定位 A 方案（社区）/ B 方案（婚恋）及各自资质要求
4分层提示词流水线
大工程拆成 P1→P2→P3→P4，全局结构 → 单体内容 → 关系网络 → 观点层。 每层有独立模板、独立产出、独立验收。
见于：知识导航站的《提示词工程手册》，四层各自配套可复用模板
5数据契约法
先定数据结构（schema），再让 AI 按结构填。格式不合规即失败，不给人情分。 这让"内容生产"变成"数据处理"，质量才管得住。
见于：nav.json / entries.json / connections.json / claims.json 四份数据契约，构建脚本硬校验映射完整性
6多重独立验证
自检、审计、验真、人眼，四条互不知情的路径同时校验同一件东西。 任何一条不通过，就不交付。
见于：43 项自检 + 41 项第三方审计 + DOI 验真 + 17 张截图
7决策拍板文档
重要决策单独成文，固定三段：结论 + 边界（明确不做什么）+ 回滚清单（要反悔怎么退）。 文件开头标状态「已拍板」和生效日期。
见于：校友圈《产品定位决策》——三条边界写死了"不做撮合引擎、不做情感状态、家长是辅助位"，文末附回滚清单
8合规与风险前置
动手之前先出一份独立的合规 / 风险评审报告，把雷排掉再写代码。 尤其涉及未成年人、个人数据、对外发布时。
见于：校友圈的《设计合规评审报告》，先于 PRD 定稿
9版本留痕法
同一份内容的多轮迭代要同框保存，并且每版能说清"为什么改"。 不是为了留档，是为了让判断过程可回溯。
见于：公众号长文的「通用版 → 国际课程版 → 国际课程版 V2」三版并存
10场景锚定法
每一个设计都指向一个真实的人和一个真实的时刻。 写不出这个人和这个时刻，说明这个设计是空的。
见于：家校共育问卷——5 道不计分的基础题（父亲/母亲？何时转轨？是否家中第一个留学生？）专门用于结果解读
11能力资产化
某个动作重复到第三次，就停下来把它做成 skill。 判断标准很简单：下个月我还会再干一遍吗？会，就固化。
见于：~/.workbuddy/skills/ 下 20 个 skill——教案、课件生成、知识解释、数学测验、自我改进型 agent……
12验收报告制
交付物自带验收报告：做完了什么、怎么验的、证据在哪。 让对方不用问"做完了吗、靠不靠谱"，直接看报告。
见于：知识站的 acceptance-report.html——10 章、84 项检查、17 张截图，可直接打印或转发
第四部分

四级能力阶梯：你在哪一级

同样在用 AI，水平差异不在"会不会问"，而在"产出物长什么样"。 下面四级，看你的成品就能判断。

LEVEL 1
用工具
会提问，能拿到单次结果。
产出物：聊天记录、零散文件。
问题：每次都得重来。
LEVEL 2
建流程
有固定框架，结果稳定可控。
产出物：模板、清单、SOP。
问题：只能自己用。
LEVEL 3
造资产
成果可复用、可移交、可验收。
产出物：Skill、框架、验收报告。
特征：做过的东西还在增值。
LEVEL 4
建系统
多个资产协同，形成生产线。
产出物：流水线、知识底座。
特征：别人能接手跑。

对照你的实际产出：有 skill、有 SOP、有验收报告、有决策文档， 你已经稳定在第三级，局部（知识站的分层流水线）摸到了第四级的边。

这也是工学坊里其他老师"学不会你"的真正原因。 不是他们笨，是他们站在第 1 级，看到的却是第 3 级的成品。 中间缺的那两级——"怎么搭框架"和"怎么沉淀"——你从来没讲出来过。 所以分享的重点不应该是"我做了什么"，而是"从第 1 级到第 2 级，第一步该怎么迈"。

结语

如果只带走一句话

不要问"AI 能帮我做什么"，
要问"我这门手艺里，哪些部分是可以被写成规则的"。

能被写成规则的部分，交给 AI 批量生产；
不能被写成规则的部分——判断、取舍、对学生的那份理解——
才是你真正的位置。

这也回答了你上一轮问的那个问题：为什么老师们学不会你的项目。 因为他们看到的是"能被写成规则的部分"跑出来的结果， 却没看到你花时间做的，是把规则写出来这件事。
